01 提案概要與目的 OVERVIEW & PURPOSE
核心假設 · HYPOTHESIS
透過「累積押注金額解鎖寶箱」的漸進式獎勵機制，驅動玩家在當日內持續押注，同時以隔日重置的急迫感製造次日回流動機，達到提升單日 Spin 數與 D1 留存率的雙重目標。
🎯
主要目標
提升新手玩家單日押注總量，透過累積門檻設計讓玩家有持續押注的具體動機
🔄
次要目標
隔日重置機制製造跨日懸念，今日未翻完的進度清零，驅動玩家次日回流繼續
📊
驗證指標
D1 留存率變化、活動組 vs 對照組單日 Spin 數差異、活動參與率、完整循環完成率
背景問題點
⚡
單日押注動力不足
玩家除日常消費外，缺乏在單日內集中押注的明確誘因
📅
次日回流率偏低
玩家無未完成任務牽引時，次日不回流的機率顯著提升
🆕
新手黏著度低
新進玩家前期缺乏低門檻回饋，習慣尚未建立前容易流失
功能定位：本次切版核心原則
玩家面 v1 只發現金獎，但後端基建一次做滿、AWC API 一次串完。v1 的 place_bet 與 v2 才會用到的 LoginWithoutRedirect 等需求一次性打包提交給 AWC 集成商，避免分兩次串接造成重複的開發、溝通與等待成本。FREE SPIN 卡的「水管」（資料表 + AWC API + max win 上限設定）在 v1 就建好，實際發卡與使用體驗留到 v2。

v5.1 v5.1 對齊後台原型 v2 · 2026-07-15
本版對齊已確認的後台原型《抽寶箱後台管理介面 v2.html》。原型 v2 為操作標準，§03 獎勵設計與 §07 後台規劃改寫為與原型一致；§16/§18/§19 同步微調。重點如下：
  1. 分眾模型改寫（§03／§07）：刪除「tag 直掛機率表、無中間映射層、多 tag 依 Priority 取最高」敘述，統一為 §15 的「標籤規則（AND 複合條件）→ 模板」映射列表 ＋ 固定置底『預設配置』（不可刪除）；未命中任何規則走預設配置，取消准入閘門（tag 僅用於選模板）。標籤池統一為 大客／中客／小客／高風險／低風險。
  2. 模板管理提升為 v1 核心頁（§07／§18／§19）：新增「模板管理（獎項與門檻）」獨立頁——模板為獨立實體、可被多檔活動／多條規則共用；「後台模板編輯（取代 Excel）」由第二迭代移入 v1 最小方案。
  3. 活動表單改 4 分頁（§07）：基本設定／標籤與配置／獎項與門檻（唯讀摘要）／版本（下拉切換＋快照明細）；多貨幣設定由活動層移入模板編輯器。
  4. 數值與驗證（§07）：門檻改累積制［100…3650］；RTP 改每模板自訂目標 ±0.1%。
  5. 監控警報改 Grafana + Telegram（§07／§18）：刪除後台「異常處理」模組與「一鍵啟停」；監控與警報以 Grafana + Telegram 值班流程處理，不做後台頁面。
  6. 審核與權限（§07／§16）：核准權由「Reviewer」改為最高權限（Admin）；第三角色正名僅查看（Viewer）；駁回原因＝必填（原型 v2 目前為選填，開發時依本規格補必填驗證）。
  7. FS 卡與獎勵歷程：模板編輯器「現金↔FREE SPIN 切換」與獎勵歷程「FREE SPIN卡」分頁標「v2 擴充（原型先行示意）」，v1 僅現金獎；§07 新增「獎勵歷程」頁（不計入 GGR）。
  8. 抽獎權重＝第 1~8 抽（§03／§07）：9 格不放回抽在第 1~8 抽後必剩 1 個獎項，後台僅設定第 1~8 抽權重；第 9 抽由系統自動決定（必中剩餘的最後 1 個獎項）為唯讀說明列、不參與合計驗證（合計為 0 檢查範圍＝第 1~8 列）；機率分佈試算與終獎落點維持 9 格顯示（第 9 格為推導的顯示性資訊、非設定值）；§03 三張示範機率表「格 9」加註為系統推導的實際機率分佈、非後台輸入值。
⚠ 相容性提醒：§03/§07 原「tag → 機率表 一層直掛」敘述已改寫為「標籤規則 → 模板」（對齊 §15）；「機率表」一詞於後台語境改稱「模板」。§04 保留舊「多 tag 依 Priority 取最高」為技術背景，並加 v5.1 註記。

解鎖門檻設計（累積押注金額）
翻牌機制（v3.2 核心）：累積押注每跨過一個門檻，玩家就獲得 1 次「翻牌機會」（非解鎖固定位置的格子）。玩家可用累積的翻牌次數，自由翻開任意一個尚未翻開的格子——可翻次數 = 已解鎖次數 − 已翻開數。沒有剩餘次數時，所有未開格顯示鎖頭、不可點擊。
為何不影響經濟：集滿當日總門檻後可翻次數累積至 9，玩家最終仍會翻完全部 9 格、拿到全部獎項；翻牌結果依機率表權重於當日解鎖時決定並寫死，玩家翻開順序不影響已定結果，RTP 與通膨風險不變。
為什麼改用累積押注金額而非 Spin 次數？
Spin 次數對不同押注段的玩家體驗差異極大——低押注玩家每次 ₱1，高押注玩家每次 ₱100，同樣的 Spin 數對後者幾乎沒有成本感。
改用押注金額後，大 R 玩家可因高押注段快速過關，機制對各押注段玩家更為公平且有感。
累積門檻（v5.1 · 累積制，對齊 §03／§07 模板）：下表 累積門檻 = [100, 220, 360, 550, 850, 1250, 1700, 2500, 3650] 為各次翻牌機會所需的累積押注門檻（PHP，各貨幣各自一套）。內部 today_wager 持續累加，取得第 d 次翻牌機會的條件為 today_wager ≥ 累積門檻[d]；本階段所需 = 相鄰累積差 [100, 120, 140, 190, 300, 400, 450, 800, 1150]，完整循環總門檻 = ₱3,650（即 9 次翻牌機會）。

UI 顯示原則：玩家畫面只顯示「再押 ₱X 解鎖下一次機會」（X = 下一累積門檻 − today_wager），進度條呈現「本階段進度」；永遠不顯示 ₱3,650 總門檻，讓玩家覺得每階段都好達成（詳見第 06 章 UI）。
幣值維度（v4.0 新增 · 2026-06-26 開案 · C3）：每套幣值（如泰銖 THB）獨立設定對應的解鎖門檻、獎池與規則——不同幣值不是匯率換算，而是各自一套配方（門檻數列、9 格獎池金額、RTP 區間皆獨立）。後台活動設定以「幣值」為一個設定維度（見 §03 資料結構 / §07 後台），同一活動概念可依幣值各開一組設定。
v4.1（2026-06-26 對齊後台原型）：以上門檻、獎池、RTP 皆為單一貨幣的設定；一檔活動可配置多貨幣，各貨幣獨立設定、RTP 各自驗算（後台以 currency tabs 切換，見 §07 多貨幣設定）。

亂數模型（方案 A：固定池 + 不放回加權抽）
固定獎池（不可變）：小 ×5（₱1）、中 ×2（₱3）、大 ×1（₱8）、終 ×1（₱18）＝ ₱37。

產生方式：玩家每日首次解鎖時，依標籤規則命中的模板權重以不放回加權抽產生 9 格排列並寫死當日 DB，當日不可重抽。翻完 9 格必得 ₱37，完成者 RTP 由該模板的總門檻決定、零變異、絕不超池。

終獎位置有機化：終獎不固定第 9 格，由權重分佈於後段（各模板分佈不同，見下表），避免每日回訪玩家看破。
後端 RTP 驗算公式（每貨幣 × 每模板各自驗算）
模板 RTP = ( Σ 固定池獎項金額 ) ÷ ( 該模板第 9 格累積門檻 )

分子固定 ₱37；分母 = 該模板的總（累積）門檻。每套貨幣（各貨幣一套）× 每個模板各自代入、各自驗算，不做匯率換算。後台即時試算，超出該模板目標 RTP ±0.1% 即警示、擋送審。
分眾架構：標籤規則（AND 複合條件）→ 模板（v5.1 對齊後台原型 v2）
v5.1 對齊後台原型 v2：分眾以「標籤規則 → 模板」映射列表表達，取代舊版「tag 直掛機率表」敘述；標籤僅用於選模板，未命中任何規則走預設配置、活動照常可玩（無准入閘門）。完整規則見 §15 玩家標籤與權限規則。

① 模板（給什麼）＝CRM 維護：每個模板含 門檻表(9格)＋權重表(9×4)＋目標RTP（＋押注比例／貨幣／版本）。模板為獨立實體，可被多檔活動與多條標籤規則共用（見 §07 模板管理）。
② 標籤（給誰）＝DA／CDP 提供：玩家分群標籤由 DA 打上（大客／中客／小客／高風險／低風險），box／CRM 不自算、只比對。

⑤ 即時衝突檢查：標籤組合重複、或規則未選任何標籤 → 紅底警示、擋送審。

養標籤套利風險（救援高倍模板必讀 · 護欄在 DA 端與結算層）：救援高倍模板讓終獎在第 3 格即可能出現，前 1%（P99）玩家在第 3 格 RTP 可達約 8%。有心人可能刻意操作自身數據，以落入命中「救援高倍模板」的標籤規則、專薅早期終獎。防線分層、各歸其位：①【DA 標籤內含門檻】 反套利門檻（近 30 天累積押注 ≥ X）內含於 DA 打標籤的條件——不符門檻者不會被打上對應標籤，其標籤組合自然命不中會導向救援高倍模板的規則；CRM 只認標籤、不自判資格；②【結算層風控】 per-模板 RTP 上限 ＋ 異常自動凍結；③【資料設計】用來選模板的標籤，其計算需玩家難以自控。模板本身不含任何護欄。
表格性質與 QA 驗收：上列各模板為固定池「不放回加權抽」下各格的邊際機率（每個模板各欄總和 = 該獎項在固定池的數量：小 5、中 2、大 1、終 1；各列總和 = 100%）。後端不以此表逐格 roll，而是依標籤規則命中的模板實作「不放回加權抽」演算法；QA 以蒙地卡羅跑 ≥ 10 萬次排列，驗證實際邊際機率落在對應模板 ±2% 內、且每次總派彩恆為 ₱37 即通過。
安全設計：洗牌結果解鎖時即寫死
洗牌結果（各格獎項內容、最終獎落點）在玩家當日第一次解鎖時即決定並寫入資料庫，後續不允許重抽；玩家無法透過重整或重新登入改變結果，避免作弊風險。累積門檻採累積制［100, 220, 360, 550, 850, 1250, 1700, 2500, 3650］、UI 僅顯示下一階段所需，不顯示總額（見第 06 章 UI）。

線路資格判定（這檔活動在哪些線路上）
規則（2026-06-24）：每個抽寶箱活動在後台勾選要投放的平台線路（platform_lines[]，多選）；線路清單為預定義「已開通 Bet=0 的平台」清單（由後端維護，營運只能從清單勾選、不可自由輸入）。玩家當下所在的線路必須落在活動的線路清單內，才會看到並能參與該活動。線路判定先於受眾 tag 判定——線路只負責先收斂「這條線路上有哪些候選活動」，再進受眾 tag 與 Priority 解析。

線路設定後台活動設定 campaign.platform_lines[]，從預定義平台清單勾選 1～N 條；必選、至少 1 條

比對邏輯玩家所在線路 ∈ 活動 platform_lines[] 即通過線路閘門；不在清單內＝該活動不顯示、押注不計入（玩家無感、不報錯）
留空處理線路為必選：未勾選任何線路＝活動無法上線（存檔即擋下，與「受眾 tag 留空＝全體」相反，避免誤投放）

受眾 tag 資格判定（誰能玩這個抽寶箱）
規則（2026-06-23 與後端對齊）：每個抽寶箱活動在後台設「受眾 tag」；玩家身上的 tag 由 DA（數據組）提供，中台不自己跑排程算資格，只負責比對「玩家 tag 是否符合活動受眾 tag」——符合才會有該活動（顯示 icon＋押注計入＋可觸發翻牌）。tag 同步機制見 CRM Roadmap §09 / W1「Tag 接收·同步」。
資格投放層＝准入閘門（v5.0）： 受眾 tag 是最外圈、範圍最廣的一次性判定，決定「這位玩家這檔能不能進場、看不看得到 icon」。本活動內含 N 組 tag → 機率表（1 個 campaign_id／1 張主題圖／1 個到期日，示範 3～7 組）；受眾准入＝玩家 tag 落在這 N 個 tag 任一即可進。行為：（a）只在「登入／投放一檔新活動」時判定一次；（b）判定通過後 sticky——檔期內只會每日切換機率表，絕不會因為某天押注沒到門檻就撤掉活動或不顯示 icon（避免客訴）；（c）薅羊毛／不押注玩家在准入這一層就過濾掉、一開始就不投放，而非進場後才消失。
准入與選表同源： 兩者是同一份 DA tag，不再有獨立的中介命中層——准入取「最外圈聯集」（誰能進）；選表取「最高 Priority 的單一 tag」（進來的人今天跑哪張機率表）。玩家從小客升大客（或反之）隔日即時換照顧，外觀無感。

15 玩家標籤與權限規則 PLAYER TAGS & RULE MATCHING
本章依 2026/07 CRM 開案會議結論撰寫 ：定義「玩家標籤如何取得、如何比對到抽取門檻與獎項配置、標籤變動如何處理」。本章的 AND 複合標籤 → 單一配置 為 v5.0 對既有 §04「多 tag 依 DA Priority 取最高單一 tag」的迭代修正，兩者並存時以本章為準；§04 保留為技術背景與資料介面說明。
v5.1 術語對齊：本章的「抽取門檻與獎項配置／設定檔」即 §03／§07 的「模板」（獨立實體、可被多檔活動與多條標籤規則共用）；「預設配置」＝後台固定置底、不可刪除、未命中任何規則時套用的模板（示範＝標準模板 A）。標籤僅用於選模板，無准入閘門。
一、標籤取得時機與匹配邏輯
項目v5.0 設計
標籤取得時機玩家每日「登錄時」，由系統向數據組（DA）取得該玩家的多組 Tag（大/中/小客、風險標籤…）。非玩家每次動作即查，登錄時取一次當日快照。
匹配邏輯（核心變更）需同時符合多個標籤條件（AND 複合條件），才對應到該組抽取門檻與獎項配置。例：（大客 AND 非高風險） → 配置 A；（中客 AND 回流） → 配置 B。單一標籤不足以命中，必須整組條件同時成立。
命中結果命中 → 套用該組「抽取門檻 + 獎項配置（9 格獎池／權重／目標 RTP）」；未命中任何一組 → 走預設配置（tag_default），活動仍可正常參與，不因未命中而消失。
資料來源一致性標籤值與分群定義由數據組提供，平台只接收 + 比對套用（非自動打標），沿用 §04 B2 原則。
二、標籤變動處理（活動進行中不即時更換）
規則：活動進行中玩家標籤變動時，「不即時更換配置」；須待活動暫停更新後，玩家「下次登錄」才套用新標籤與新配置。
為何這樣設計（設計動機）：
  1. 避免影響進行中的活動：抽取門檻與獎項是「一整檔活動」的經濟模型參數，中途換配置會讓同一位玩家在同一檔活動裡出現「規則不一致」，破壞公平性與可預期性，也讓客訴與對帳難以歸因。
  2. 保護已累積進度：玩家當日／當檔已累積的押注進度與已解鎖翻牌次數，是依「命中當下的門檻」計算；即時換配置會使既有進度對不上新門檻，造成進度倒退或暴增的體感落差。
  3. 可控的切換點：把「換標籤」收斂到「活動暫停更新 → 下次登錄」這個明確切點，讓營運能預期何時生效、便於公告與風控，避免運行中資料在飛行中被改寫。
三、規則階段性與未來規劃
🟢 初期（本次範圍）
採「一層複合標籤規則」：多標籤組合 → 單一設定值，避免規則樹過於複雜。
標籤範圍先只做簡單分類：大客 / 中客 / 小客 ＋ 風險標籤。
🔮 未來規劃
導入分群模型，由模型輸出核心標籤供系統直接調用；
但保留規則兜底機制（rule fallback），確保模型異常或標籤缺失時活動仍可控可預期。

二、預算來源：RTP −1% 守恆原則
守恆原則（務必明確）：活動上線後，將相關線路或標籤玩家的 RTP 調降 1% 作為獎勵預算來源。此為「挪移」而非「加碼」——整體 RTP 佔比不提升：從既有 RTP 撥出 1% 轉為 CRM 活動獎勵，總支出守恆，不新增整體 RTP 成本。
BDD 驗收情境 · RTP 守恆
Given 某線路基準 RTP 為 X%
When 該線路/標籤玩家納入抽寶箱活動、RTP 調降 1%（X−1）%，活動獎勵預算 = 該 1%
Then 「遊戲內 RTP（X−1）% ＋ 活動獎勵 1%」= 原 X%，整體 RTP 佔比不變；對帳可驗證兩者相加守恆。
